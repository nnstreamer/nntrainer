BOUNDARY AND CONTRACT
The existing lfm_m1_setup guard alone selects the new call: native LFM M1, K2048/I1536/N2048, SiLU, the existing 64-expert registry and active-count/row constraints. Unsupported/Gemma/prefill calls retain the original full reset. No new storage, capacity, reader, cache, allocation, DMA descriptors, or arithmetic. try_reset skips the 256 * 128 = 32,768 byte memset only after observing a valid completed actual last descriptor; it resets indices, tail and started state. It is neither a wait nor an error-handling repair.

The proof uses the existing serialized, single-owner ring and ordered linked-DMA completion contract. last = (push - 1) & 255 is valid over wrap, including push == 0. BSS NULL, the type-zero reset sentinel, a nonmatching tail, wrong size/type, and done == 0 all return zero without modifying ring state. No push/pop equality shortcut is used. On success, tail == NULL and started == 0 force the following push through dmstart. On refusal, the caller performs exactly the original reset. Ordinary wait/drain/push implementations are untouched.

DESCRIPTOR AND ORDER REVIEW
Every push fills every semantic hardware field before submission: next, size, type, compression/bypass/order/done, both reserved fields, offset, source/destination pointers, strides, row size and both row-count halves. done is explicitly cleared even when old descriptor bytes are retained. The actual v81 object writes all eight 32-bit words of the 32-byte hardware descriptor before the existing cache-clean, release and start/link sequence. The target sizeof/alignment assertions independently confirm 4-byte pointers, 128-byte descriptor stride/alignment, src at 8 and dst at 12. The remaining 96 bytes are alignment padding, absent from the declared size-one descriptor fields and untouched by fill; cache-line maintenance is not semantic consumption of padding.

The new completion read is the existing volatile is_done read. Actual v81 code tests it before publishing reset software state. Existing fill/cache/release/submit instructions are unchanged. Note that Hexagon release(Rs):at has a store effect, not merely fence semantics; the fixture's release mock does not reproduce its hardware pointer-word store. Thus the host test proves C field initialization and ordered submission under the mock contract, not literal DMA wire-format execution. Existing production release and dmlink sequences were not altered.

LIMITS
The existing finite ring wait/drain API can time out without propagating an error. If try_reset refuses an incomplete ring, fallback retains the original full-reset behavior; it does not make a previously unsafe timeout cleanup safe. Delayed DMA after such an existing failure, hardware visibility/coherence, scheduling concurrency outside the existing ownership contract, and real device correctness/speed remain outside this host review. The emulator completes pending work before its cleanup checks and does not establish safety of clearing live hardware descriptors. Last-descriptor completion implying earlier linked completion is the existing hardware contract, not a new physical-hardware proof. No TPS or measured bandwidth gain follows from removing a logical 32 KiB clear.
