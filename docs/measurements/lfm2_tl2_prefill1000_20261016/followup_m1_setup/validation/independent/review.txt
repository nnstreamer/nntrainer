Ownership and branch proof
- use_tl2 inherits use_m1, nonzero n_with_rows and M==1. The new guard further
  requires 2048/1536/2048, 64 experts, 1..4 active native-TL2 pairs, widest==1,
  no affine offsets, and SwiGLU. Validated row_index entries must therefore
  all be zero. Gemma, prefill, mixed QS2/TL2, affine, repeated expert rows and
  non-M1 fallback execute the original setup. No ABI or platform API changes.
- The carve layout, reserved need, n_slots capacity, 64-slot per-expert stride,
  per-expert scratch and VTCM layout are unchanged. M1 disables shared slots,
  so d==slot_of[i] and advancing by padded=64 still initializes each consumer's
  unique row-zero scale/zp. There is no new cache, buffer, persistent state or
  generation/lifetime protocol.
- All-native GU constructs one dense activation LUT and skips AH packing.
  slot_row and pack_skip are never read on this path. The generic HMX pack
  consumers are after the M1 return. GU epilogues use m_count=1, and the actual
  hvx_dequant_i32.c scalar parameter reads select scale/zp[0] only. DN uses its
  separate per-expert requant scale/zp. Quantizer m_pad=1 changes only padding
  defaults; m_valid=1, row-zero computation and dense activation bytes remain.
- rows_out writes each output directly after its required y memset, preserving
  the exact 0 + weight*result arithmetic and order. It then jumps to common
  cleanup before out_c is read/copied. Ordinary accumulation still clears
  out_c; ordinary zero-expert output still clears/copies zeros. Zero-expert
  rows_out still returns the existing EUNSUPPORTED before any writes.
- GU(0) asynchronous DMA only targets the existing VTCM weight slab. Quant is
  inline with NULL pool while that worker owns the pool, then the same join
  occurs. No submit/join, timeout drain, scratch growth or reuse order changes.
  Common exit does not read skipped metadata. The existing pre_gamma M1 path
  normalizes the row before quantization and is included in the checks.
- Integrated router handoff excludes use_m1. Its input-prefix carve therefore
  cannot change this candidate's M1 offsets; the combined diff was inspected.

whole-kernel runner suppresses only shift-base in the scalar stand-in TU;
all checks remain on for both production MoE TUs and the actual quantizer.
The original baseline diagnostic is retained at the author's
checks/san/known-shift.log. The independent real HVX epilogue uses neither
that scalar routine nor this suppression. SDK libnative does not reproduce
real DSP cache coherence, asynchronous overlap, clock or thermal behavior.
Full-model IDs, repeated prompt state and actual speed remain parent's
required device gates. No Gemma device rerun or memory/cache increase is
needed to validate this narrowly guarded LFM-only candidate.
