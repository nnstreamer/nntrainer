Code findings
1. Guard and layouts
   moe_tl2_gate_direct admits only native K2048 (k_tiles64), I1536 (48 pairs),
   N2048, split1, row1, SILU, and both native weight handles with magnitude1.
   The nonfused caller additionally requires one aligned, whole-expert range.
   The existing native GU worker writes contiguous gate[1536], up[1536] for
   split1. A 128-byte tile stride and n_pairs48 therefore address exactly the
   same two 32-int32 tiles as each original stack copy. Metadata indices are
   cg=32*j and cu=1536+cg in both paths. The new helper's job is synchronous.

2. Exact arithmetic and work ownership
   Both implementations call the same production hvx_dq_swiglu_worker and
   dq_swiglu arithmetic. The candidate removes the identity magnitude1/split1
   assembly into the temporary stack tile and repeated NULL-pool wrapper.
   For nonfused expert e and p lanes, old global tile bounds are
     48*e + floor(48*id/p) .. 48*e + floor(48*(id+1)/p).
   The new worker uses the same local bounds and expert e's pointers. All
   accepted geometry is small enough that the old uint32 partition arithmetic
   and the worker's uint64 arithmetic have identical results.
   In the fused branch the existing lane still owns the same expert and calls
   worker(1,0), then the original quantizer and LUT preparation in that order.
   It does not split calls or change down computation/final expert sum order.

3. Lifetimes and synchronization
   acc_gu is carved from each expert's persistent-for-this-call M1 scratch,
   separately from the VTCM GU/DN DMA slabs. Stage A's existing pool/queue run
   joins before nonfused epilogue dispatch; all A runs finish before fused B.
   Thus even when B overlaps a later weight DMA, the direct source is not that
   DMA slab. Parameters and gate output remain per-expert and alive through B.
   No job escapes the helper, and no worker can read its stack job after return.
   No pool dispatch/join, DMA ownership, error drain, cancellation, or cleanup
   was removed. Allocation failure and existing DMA error behavior are unchanged.

4. Fallback and platform scope
   Gemma K2816/I704/N2816 and GEGLU, split2/4, magnitude7 on either handle,
   non-native/missing native handles, multirow, or partial/cross-expert ranges
   continue through the original epilogue. Same-call mixed native and QS2
   experts are handled independently; only qualified native experts use direct.
   There is no new heap/VTCM/cache allocation, reader, public API, ABI, external
   symbol, operating-system header or host-side behavior. The production change
   is confined to the existing DSP translation unit. Gemma arithmetic/fallback
   is preserved by inspection and host parity; this is not a Gemma timing claim.

Limits
  These fixtures validate primitive math, layout, guard selection and ownership
  under explicit host lanes. They do not emulate RPC, DMA cache visibility, QuRT
  queue timeouts, whole-token graph execution, or silicon timing. Host libnative
  execution is not evidence of TPS gain. Source inspection establishes that the
  existing pipeline joins/drains are unchanged; root owns the required phone
  parity and normal A/B measurements. No speedup is inferred in this report.
