LFM compact i24 DN scatter: balanced aligned groups
=================================================

Ready for device evaluation, not a measured whole-model gain.
Base 03d652fc0. Only moe_dn_fg_worker changes (one 19-line replacement).
Apply scatter-row4.patch; do not copy the whole source over concurrent work.
The separate router-input handoff and the app top-k experiments are untouched.

Scope and ownership
-------------------
The new branch requires acc_i24, N_out2048, tile_stride6144 and at least four
rows per worker. In this source, a 6144-byte ring is created only for the
native-TL2 non-affine SiLU M>1 K2048/I1536/N2048 case with 32 accumulator
tiles and proven i24 bounds. Gemma GeGLU, int32/native8192 and smaller jobs
retain the original split. Source comments document this shape guard.

Each worker first consumes an equally sized multiple-of-four prefix,
then its share of the remaining rows. Four-row i24 groups use three plane
loads and reuse all four restored vectors, instead of loading planes and
using only one row at a worker boundary. Each worker receives EXACTLY its
original number of rows. The row sets are disjoint and cover the block.
The final partial group uses the existing scalar-row vector path.

Within an expert the token rows are unique. Worker ownership may change,
but each output row still receives the same expert additions in the same
order. Inter-expert foreground jobs remain sequential. The unchanged
requant worker still executes first on the same lane with the same slice.
Submit/wait and all gate/mid/accumulator lifetimes stay unchanged. The
native-TL2 path disallows the separate HVX tail-expert path, so splitting
row intervals cannot duplicate tail scatter. Shape guards preserve other
models' worker split and arithmetic.

No heap, VTCM, ION, persistent cache, ring, reader, preload or worker-count
increase. Production v81 worker frame is 32 ->40B (+8B transient stack);
this is not a full stack peak estimate. C16/PAGE0/Direct I/O remain fixed.

Rejected first split
--------------------
The naive fully aligned split reduced reconstruction operations by51.8%
and lane busy cycles by16.0% at seven workers, but put12 rows on one lane
for a64-row block. Weighted maximum-lane cycles regressed3.70%. It was not
sent for device application. candidate-naive.c, scatter-row4-naive.patch
and sim-final/ preserve it. The first large simulator launch in sim/ was
stopped because full-buffer verification dominated simulator runtime; no
numbers from that incomplete run are used.

Correctness and builds
----------------------
* host-san-balanced/: actual HVX/libnative, ASan+UBSan,24576 cases x3 repeated
  contributions: rows1..64, workers1..8,3 FP input patterns (including
  subnormal and large scales),4 seen modes, compact6144/native8192/N2816/
  int32 paths. Outputs, seen bits and read-only planes are byte-exact.
* A further240 cases x3 use the REAL worker pool (0/1/3/7/8 workers), all32
  tiles and boundary row counts. All exact. The unchanged requant worker
  is mocked solely to verify original lane ownership/call count; its
  numerical quantizer is not retested by this fixture.
* sim-balanced/:5 selected compact exact boundary cases x3 (m1/4/16/63/64),
  plus the full m1..64/worker3..8 timing matrix. The common console suffix
  says shapes=4/rows1..64 from the host matrix; simulator exact coverage
  is the five selected cases, while timing covers all64 row counts.
* partition-proof.json:4160 cases m0..64/lanes1..64 prove every row is owned
  once and each lane's row count matches the original exactly.
* mutation-balanced/: deliberately shift tail start by one; assertion fails.
* Full production MoE source compiles v81 -O3 -Wall -Werror. Same repository
  clang-format14 applied only to the changed function. No device access or
  root modifications. Source/binary/command hashes are retained.
