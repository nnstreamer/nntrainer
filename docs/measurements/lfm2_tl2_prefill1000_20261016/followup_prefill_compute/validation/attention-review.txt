## Safety reasoning

Optional detail is requested only by trace mode. Existing lengths >=8 remain valid, 8..19 write only the original eight slots, >=20 writes exactly twelve further slots [8..19]. The 96-byte prefill_stats struct is zeroed before either decode or prefill; decode details remain zero. The 20-slot host array adds 48 stack bytes. Error paths return before stats writes. Existing clients requesting eight slots remain compatible; a new trace-enabled client should use the matching new DSP skeleton for meaningful detail fields.

Store partitions use uint64 arithmetic and disjoint [lo,hi) row ranges. The row-to-query/head mapping is injective for each KV head and skips padding before reading l or dividing. Each 64-dimension head stores two nonoverlapping 128-byte vectors. The existing last pquant job has synchronously joined before PV and store. hvx_worker_pool_run first waits for an old job and waits for all workers with release/acquire completion before returning; the stack store_ctx remains alive throughout. Output scalar reciprocal and vector multiply order are unchanged.

Q-prep retains the separate quantizer's default scale=1 and zp=0 for real and padded zero rows; its guard confines the new helper to full, dynamic-Q8 LFM geometry. The helper dispatches four-row groups without changing arithmetic. Fixed-Q8 Gemma and other shapes follow their original branches. No new weight storage, expert-cache capacity, or persistent scratch was introduced by this diff.

## Narrow limitations

The host checks do not emulate HMX, QuRT scheduling on device, cache coherency, or FastRPC marshalling. Parent's matched DSP build and 21 exact device replays provide device evidence separately. This audit does not assert bit parity for arbitrary NaN/Inf model tensors, nor bidirectional optional-detail compatibility with an older DSP skeleton. IDL's existing comment still lists only the original eight stats; documenting the twelve optional slots would improve the diagnostic contract, but is not a correctness blocker.
