The fixture now derives all block dimensions from named HMX constants: ROW=64, COL=32 and INNER=32, matching `hexkl_micro.h`. In particular, I1536 has 48 inner tiles. The change only touches the host fixture; all production source hashes remain identical to production-remapped.patch b0fe2e2e.

The corrected 176 cases passed ASan/UBSan in `checks/ninner32-run.log`. The 18 deliberate mutants were previously checked against the same production code with the old fixture geometry; that broader suite was not repeated for this test-only constant correction. The one affected prefix-carve mutant was rerun and rejected at `FAIL: carve total differs from same reserve sum`; its exact command, source hashes and result are in `checks/ninner32-prefix/result.json`. The old tests-remapped.patch (4138ad04) is preserved, and fixture-ninner32.patch is the small delta.

The remaining substitutes are deliberate and limit what these host tests establish:

| Area | Host fixture | Scope / independent evidence |
| --- | --- | --- |
| Background job/context types | `hvx_bg_job` is an opaque 64-byte array; `moe_tail_ctx` is an opaque 256-byte array. Actual v81 sizeof is 32 and 64 bytes. | The same substituted sizes are used by extracted original/reuse carve code. This checks ordering and retained-input aliasing, not exact device capacity. The original sizing expression is separately compiled with real v81 types/macros in `checks/scratch-cap-audit/`. |
| Pointer/ABI layout | Actual extracted ownership and scratch structs compile with host pointers/size_t. `remote_handle64` addresses a local fake session. `moe_tail_shared` is a host-pointer aggregate. | Native host layout is not the 32-bit DSP ABI. Real NDK/v81 objects and sizeof probes establish target compilation and fixed metadata size separately. |
| Session/weight table | Minimal session fields, one compact/noncompact flag instead of the real weight registry, six-worker count without background worker execution. | The test exercises actual RPC validation and compact-path guards, not HMX weight decoding, worker concurrency or registry ABI. Full existing `swap_host_check` was run separately against the real RPC/registry code. |
| Input/output storage | `HtpRpcBuffer` uses a vector or test-owned shared mapping; allocation uses malloc with failure injection. Linux remapping tests use three real `MAP_SHARED` mappings of one file. | Checks source lifetime, byte equality, alias rejection, fallback and no added handoff allocation. No Android ION allocation or FastRPC remapping/coherence implementation is simulated. |
| DMA and compute | Synchronous memcpy replaces DMA; router/norm/attention and MoE arithmetic are controlled stand-ins. MoE copies the selected full input to output for byte comparison. | No claim of model arithmetic parity, target cache coherence or speed from the host fixture. Root device IDs/trace/timing are separate evidence. |
| Service metadata | Mock profile level/backend handle, local return-code enum, no-op logs/probes and clocks. | Preserves branching and failure-invalidation checks, not the binary layout/value contract of production services. |
| Large writer methods | Actual before-write lock/invalidation prefixes are extracted for queue/materialization paths; subsequent destination writes are simulated. Full sync/direct-attention/id methods are extracted. | Covers the ownership boundary and exceptions tested, not full queue scheduling or materialization arithmetic. |

These limits are why the copy-skip parser uses the separately compiled original v81 capacity table rather than host-fixture allocation sizes.
