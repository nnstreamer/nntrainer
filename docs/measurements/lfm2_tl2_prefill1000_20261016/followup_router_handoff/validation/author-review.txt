Opt-in: `NNTR_LFM2_ROUTER_INPUT_HANDOFF=1`. It reuses only the input bytes already copied by the existing eligible FP32 LFM router into the existing DSP scratch prefix. C16, PAGE0, preload128, reader count, weights, arithmetic, routing order and expert caches are unchanged. No activation allocation or persistent content cache is added. ## Proof and boundaries

- ARM serializes producer/consumer with the existing `invoke_mutex_`. Each eligible producer gets a never-reused 30-bit ticket. Exhaustion disables reuse permanently for that owner. A record binds that ticket to session, actual ION source, byte extent, and write epoch.
- Writable `stage`, input copy/swap, buffer replacement, prompt start and prefill staging release invalidate the record. All direct output writers also invalidate before their first write: `sync_to_host`, both direct attention methods, public prefill materialization, u16 output-projection materialization, queue `tokenForward`, and `take_decode_token_id`. The existing `stageInput` no-write return alone preserves it. `sampledSame` is unchanged and is **not** the new equality proof. An unsampled CPU mutation that baseline staging ignores leaves both paths reading the same original ION bytes; the fixture explicitly checks this case.
- Consumer captures and consumes the stamp after its actual input staging decision, even when another guard declines reuse. Output staging owns a distinct `unique_ptr` allocation. Before obtaining it, the candidate rejects any kept-host restore destination overlapping the input ION. The producer rejects either the original input x or logits output overlapping its actual ION input. Direct/caller-writable ION input cannot provide an exclusive owner epoch, so it always falls back. These are metadata range checks, not content comparisons.
- DSP uses a separate `htp_router_handoff_scratch` type/API and consumes an independently published one-shot stamp matching the ARM-authorized ticket, byte extent, scratch allocation identity and scratch epoch. It never treats an RPC input VA as persistent ownership: the same ION receives different DSP VAs across router/plain RPCs on the actual device. The paired ARM client must first consume its source-bound stamp against the actual ION source, session, extent and write epoch before transmitting the ticket. DSP independently validates its retained scratch. This is an internal trusted paired-client contract, not authentication against a caller fabricating tickets. Router success publishes only after the existing synchronous input DMA, router workers and logits copy finish. All scratch reservations, including no-growth reservations, and scratch free invalidate. Plain/norm/conv validation failures and alternate routers invalidate. Registration/rebind remains the permitted gap: those functions touch weight storage/VTCM, not `moe_scratch`.
- The core checks native compact TL2 for **every active expert**, exact K2048/I1536/N2048 SwiGLU geometry, M128..4096, no norms/direct output/M1, and `need <= existing cap`. A scratch growth, unsupported profile/shape/kind, missing/mismatched ticket, interposed write, malformed activation word or repeat cannot reuse.
- Borrowed `host_view` pointers remain const/read-only and valid only until the next engine call (`compute_ops.h` contract). Writing through an expired/const-cast borrowed view violates that existing ownership contract and is outside this proof. `get_htp_ops()` supplies one process-wide compute owner; its existing mutex serializes dispatch.
- No runtime RPC signature or generated stub layout changes. `n_sel` with router `top_k=0` and plain MoE `act` carry the same new ticket word. This is a wire **semantic extension**: deploy matching ARM and DSP binaries. An old DSP rejects the tagged plain activation. Default/off still sends the original 0/1 values. Gemma E128/K2816/GeGLU/fused norm paths never request the ticket; no repeated Gemma benchmark is needed for this candidate.

## Layout and performance interpretation

**OFF preserves the original scratch carve order and input DMA.** ON moves `act_c` to the existing scratch prefix only on an actual validated hit, and skips its input DMA only in that same branch. All fallback paths preserve the original order and copy. Total reserve size, alignment, and remaining buffers are unchanged; there is no layout-only switch. Therefore an ON/OFF time difference combines copy removal and hit-only layout movement. The proposal's ~12.8 ms/38-layer benefit is a hypothesis derived from half the earlier combined input/output staging figure, not a measured gain or strict bound.

## Parent device plan and exact trace accounting

Build the DSP RPC TU with `-DNNTR_LFM2_ROUTER_HANDOFF_TRACE=1` for one diagnostic run; leave it undefined (or 0) for normal timing. Tags contain `nntr` for the current logcat filter:

- `[nntr-router-handoff-producer]`: M, ticket, cached, bytes. A normal single 1024/2048 block has **38** real router lines and no load warmup router.
- `[nntr-router-handoff]`: M, ticket, request, owner (DSP stamp matched), used (actual DMA skipped), fallback, bytes, cap_before/cap_after, rc. Expected **39** plain lines = **1 load warmup with request=0** + **38 real layers with request=1**. M1 decode is excluded from these tags.
- At M1024 the warmup E64 × 64 rows and real top4 × 1024 both have 4096 routed rows, so the expected real hit count is 38 when the retained scratch survives all intervening operations. Producer and consumer RPC mapping VAs may differ.
- At M2048 the real route count is 8192 while warmup remains 4096. The app compacts away experts with no rows, so the unchanged sizing expression `n_slots_cap = n_rows + n_experts * 63` can grow scratch on multiple successive layers. No fixed 37/38 hit threshold is valid. A fallback must retain a valid stamp and grow to a capacity reproduced by the original v81 sizing expression; a copy without growth is rejected.
- The state tag uses only M/K guards and therefore includes additional unticketed dense calls that the native-LFM consumer tag excludes. The observed 42 state lines are 38 requested states plus 4 unticketed states (one warmup, three dense); only requested states join the ticket bijection. The revised `[nntr-router-handoff-state]` success mask is **31**: saved ticket present (1), ticket equal (2), scratch epoch equal (4), allocation owner equal (8), extent equal (16). `source_scope=arm` names where source identity is verified. `[nntr-router-handoff-publish]` prints the producer RPC input address for diagnosis only.
