Transport bound and pairing
V2 changes only serialization: two FARF records keyed by the already captured
64-bit start tick. Geometry is G, raw phase timing is T. Both end in an explicit
! marker; ticks/ID are hexadecimal and geometry/counts are decimal. Actual
extracted C formatter run with full uint32/int32/uint64 limits produced188
and167 characters, below parser's192 and observed transport limit228.
This leaves40/61 characters relative to the observed trace payload ceiling.
No new timers, mutable global ID sequence, allocation or cache is introduced.

Parser pairs by full ID rather than adjacency. It accepts reordered/interleaved
G/T records but rejects duplicate IDs/parts, orphans, missing counterparts,
malformed tags/fields, out-of-range integers, bad terminal markers, v1 data,
nonzero rc/fallback geometry and invalid phase sums. Exactly180 unique pairs
and360 complete records plus the expected warmup/main shape distribution are
required. An ID collision is rejected rather than combined ambiguously.
A deliberately balanced exchange of two intact IDs is not cryptographically
detectable; normal transport is assumed to preserve the payload bytes. This
is not an integrity checksum or a substitute for generation/exit-status checks.

Interpretation and conservative bounds
The raw body excludes early validation/allocation and both final logs. The
five measured intervals do not overlap on the foreground thread. Background
DQ/DMA service time is already hidden in other work and cannot be summed in.
The60.5ms remainder includes required HMX issue/compute, ordinary loop work,
submits and instrumentation. It is not all removable overhead.

For an accumulator-read-only change,27.5ms is a loose impossible-zero-cost
ceiling under otherwise unchanged timing, not an i24 prediction. It includes
HMX completion waits and timer cost. Under a narrower bandwidth-proportional
assumption, replacing4-byte stores by3-byte stores gives an optimistic25%
of the storage part, at most about6.9ms from this read bracket before any
conversion/extra scheduling cost; storage's actual share is unmeasured.
This arithmetic is a conditional opportunity scale, not a measured saving.
An i24 change may move cost into the9.4ms exposed join, so read+join must be
assessed together. There is no i24 implementation in this work.

The separate fast-issue investigation targets provable per-kt control work,
not this entire60.5ms remainder. In actual baseline v81 assembly, alignment
mask arithmetic is already outside the kt loop; predicate/branch, descriptor
setup and two stack reloads remain inside. For main1024,148480 output tiles
*64 kt =9502720 issue steps. A candidate needs actual codegen/packet-address
parity before timing; no speed claim follows from this count.
