Scope and buffer bounds
The guard selects dynamic Q8, full-cache LFM geometry, n_q >=1024 aligned to128,
32 Q heads /8 KV heads /head_dim64, no window/softcap/sinks, BR128/BC256/G_BR512,
and at least one actual background worker. Gemma/fixed-cache/Q4/small-prefill
paths retain serial conversion. No new host/Linux APIs or build dependencies.
The planner gives8 row tiles *8 column tiles *8192B =524288B raw readouts.
Qx capacity is chunk *512*64*4:1048576B for1024 tokens (chunk8),1179648B for
2048 tokens (chunk9). raw<=qx plus qx<=total<=cfg and raw<=total-qx are checked.
Each8192B tile offset is2048B aligned and remains before the HMX config area.
The usable acc layout validates every64x32 source index inside one8192B tile.
The two score tiles written by each (row tile,column tile) are disjoint from
all other workers' outputs and from raw Qx, P, O, q_ah, KV and L.acc.
No new heap/VTCM allocation or extra weight/cache storage is introduced.
Actual v81 -O3 -fstack-usage: entry frame1536B vs1408B (+128B), phase_qk512B
unchanged; new dequant_worker384B, below existing softmax_worker1920B and the
existing32KiB pool stack. These are compiler frames, not full call-chain peaks.

Lifetime and synchronization
phase_qprep gathers and completely packs the whole Q chunk, using synchronous
hvx_worker_pool_run, before any Q block runs. Subsequent QK reads q_ah, not Qx.
q_scale/q_zp stay in distinct metadata storage. Even a partial final chunk
can reuse Qx: its valid rows were already packed and no later phase reads them.
The first QK block is still serial. Each next-QK readout writes Qx while the
current softmax writes the current S bank. softmax_finish_pquant joins softmax
and finishes synchronous P quantization before the new dequant submit.
Dequant workers read Qx and q metadata and write only the other S bank. The
caller executes PV using L.acc, P, O and a/p_scale metadata. No new DMA/HMX
operation runs on workers. The pool has a single foreground job; no nested
submit occurs from dequant_worker. q_i, shape, layout, head metadata and the
stack dequant_job stay fixed until wait completes.
After PV, wait executes before checking rc: success and PV error both drain.
An error in first QK has no active job; an error in next QK joins the current
softmax before returning. No worker survives run_q_block into a new q_i,
Q prep, metadata free or caller stack reuse. End-of-loop store is after joins.

Arithmetic
The serial dequant_s body is preserved in dequant_s_at; only the accumulator
base becomes an argument. Each tile retains int32->FP conversion, zero-point
correction, scale products and fp16 narrowing order. Tile order is parallel,
but tiles have no reduction between them. Softmax block order, P quantization,
PV accumulation and final output order remain unchanged. Numerical validation
uses the extracted original serial HVX converter as reference.
