What changes, and what remains the same
The actual incremental caller passes the opt-in only for ARM+HTP, first-block
batch-one native TL2 LFM, sigmoid/SiLU, top4/E64, hidden2048/inter1536, folded
input norm, one input and no router norm/output norm/output add. The helper
checks the already-flattened rows [M,1,1,2048], M1024/2048, FP32/NCHW/contiguous,
the actual nonnull HTP ops pointer and all 64 GU plus 64 DN metadata shapes and
TL2 types. Unsupported shapes and Gemma remain on the original path.

The new private method argument defaults false. Null extra output, E other
than 64, and a nonempty incoming hint preserve the old append behavior. The
mask shifts only IDs initialized as 0..63 in the existing scored array. Every
row still computes the identical sigmoid, bias, partial_sort prefix9, top4
normalization and token/weight assignments, including after all 64 bits are
seen. The extraction runner proves the per-row FP/selection source body is
byte-identical, and the actual method executes against the same STL/libm in
the parity fixture. Only materialization of the unused duplicate hint IDs is
changed. The downstream full-vector reverse, Weight-key conversion and single
ExpertLru::refresh call are unchanged.

Policy proof, aliases and observers
Let S be the original token-major, rank-major ID stream and U preserve each
ID's first occurrence in S. refresh visits reverse(S) and moves each resident
key to the list back, so its last touch wins. The resulting order is governed
by FIRST occurrences in S. The nearby old comment about the last token does
not describe this actual operation; this candidate preserves the operation.

For a key k shared by multiple expert IDs, its first position in S is the
minimum first position of those IDs. That position survives in U, so relative
first-key order is also preserved under aliasing. Reverse(U) therefore has
the same effective last touches as reverse(S). Nonresident keys can be
discarded from either stream, and untouched residents keep their prior order.

Keys are addresses of Tensor objects returned by getWeight, not data pointers.
The context lookup and Var_Grad::getVariableRef return the existing object;
there is no deduplication by tensor storage. Distinct Tensor objects sharing
data stay distinct, while repeated indices or shared Tensor objects are
covered by the alias proof.

The actual generic ExpertLru header is byte-identical. refresh holds one mutex
for the entire key sequence. Its touch operations change only the list and
stored iterators, not score_, clock_, held_, capacity_ or layers_. Equal final
order therefore also preserves future LRFU ties and eviction behavior under
the same subsequent operations. order/resident/size/room/acquire/makeRoom/
hold/unhold/reset use the same mutex; intermediate duplicate splices are not
observable through these methods. No callback, iterator, new per-key locking
or resident-query race is introduced. Tests do not constitute a TSAN proof;
the lock-scope conclusion is a source proof supplemented by real observers.

Tracing and fallback boundaries
An exact cached env value NNTR_LFM2_COMPACT_PREFILL_RECENCY=1 is required.
Both a nonempty NNTR_MOE_TRACE request and an already-open moeTrace() FILE
disable compaction. This covers a failed fopen and an open file whose env was
subsequently unset. Normal forwarding and assignmentsFromRoute are unchanged.
The helper and actual caller are compiled out outside ARM+ENABLE_HEXKL; the
portable method's default path remains generic. This is a semantic guard,
not proof of zero fallback timing overhead or unchanged Gemma throughput.
Windows was source-reviewed for the guards, not independently built here.

Cost and capacity
No activation or expert buffer, persistent data cache, reader, C setting,
preload, layout, LRU capacity or score state is added or changed. The two
existing temporary hint vectors shrink logically from 9*M IDs and pointers
to at most 64 each. On AArch64 this is 36/72 KiB of IDs and 72/144 KiB of
pointers at M1024/2048 versus at most 256+512 bytes, before allocator growth.
These are logical element counts, not measured peak-memory savings.

There is one local uint64_t mask. The independently compiled ARM assignment
frame is 528 -> 544 bytes (+16), while incremental_forwarding stays 3,008
bytes. llvm-nm reports a 1-byte cached opt-in boolean and its 8-byte static
initialization guard; segment alignment may add padding. The metadata guard
reads 128 existing weight descriptors and the hint still performs prefix9
selection for every row. No speedup follows from these counts alone.

Resolved during review
The first draft tested [1,1,M,H] after the production caller had already
reshaped to [M,1,1,H], so it could never qualify. The frozen guard is corrected.
The source-based fixture now preserves reshape-before-caller order in one
include, validates reshape element count and synchronizes its observer after
the first actual snapshot. Both trace-state exclusions are present. These
were corrected before the frozen hashes reviewed above.
