LFM native TL2 stable-pair metadata refresh
=========================================
Base: b464fbf6f (production file byte-identical to the saved before/ source).
Scope: hexkl_mm_u8i4_dma.c, hexkl_weight_tl2_refresh_pair only.
Production patch SHA256:
323a6e2b94b52de3796ca8e4f658f7db3d30f496129106112d3bd490177dfe57

Change
------
Inside the pre-existing stable-generation and LFM K=2048/I=1536/N=2048
validation, issue GU scales+sums as a 12288-byte by 2-row DMA and DN as an
8192-byte by 2-row DMA, then drain both. Previous code used four single-row
DMA descriptors and two drains. Total payload stays 40960 bytes per changed
pair. The immutable +0 bias is no longer rewritten (20480 bytes per pair).
Initial register/rebind still initialize all metadata and zero bias.

No change to registration, handles, arena ownership, generation publication,
source/destination storage, reader count, cache size, precision, IDL or ABI.
No new heap, VTCM, arena, static cache or runtime flag. The compiled refresh
stack frame changes from 48 to 64 bytes (+16 bytes). Descriptor and cache-line
bounds are satisfied by the existing shape guard; no broad model dispatch.
Gemma and non-stable handles retain the original no-generation no-op.

Correctness reasoning
---------------------
- fill_slot allocates the scales/sums/bias consecutively in a 128-byte-aligned
  allocation. Each LFM metadata row is a multiple of 128 bytes. The native
  source tail similarly stores scales followed immediately by sums. Each
  two-row extent ends before bias, so invalidation does not discard its
  initialized +0 cache lines.
- Compact register and compact rebind are the only production paths setting
  tl2_compact. Both call the existing tail helper, which zeros bias. Legacy
  rebind clears compact/generation, and transitioning back through compact
  rebind reestablishes +0 even after a caller-supplied nonzero legacy bias.
  No kernel writes registered bias. Affine offsets reject bits==2 handles.
- Both source ranges are invalidated before either DMA starts; destination
  ranges are invalidated only after the one drain completes. Generation_seen
  is stored last. No-change and validation-failure behavior is untouched.
- A moved compact arena clears the old generation pointer and reads the new
  metadata through the existing rebind. Attaching the new generation then
  uses the same refresh ownership rule. The host must continue publishing
  payload before generation; this patch does not change that contract.

Limits and interpretation
-------------------------
The DMA API already returns void; its internal guard timeout is not surfaced
as a failure. This patch preserves that existing limitation. Host deferred
DMA validates software ordering, not the physical cache/DMA hardware. Device
validation belongs to root. Root reports normal A/B IDs and same-handle tests
exact with no peak increase, but timing attribution is still measured by
root's separate refresh-loop diagnostic. Do not equate the existing ~67 ms
GU/DN weight-drain bucket with metadata refresh or claim it is eliminated.
