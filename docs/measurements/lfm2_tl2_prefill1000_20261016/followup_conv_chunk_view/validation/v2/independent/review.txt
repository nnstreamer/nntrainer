What was reviewed
  Only the app convolution file changes. At the existing affine LFM
  K=C=N2048 route, the new function is selected for contiguous FP32 M2048
  on AArch64, both affine projection weights, !compare, backend capability,
  and !(htp_owns_state_ && from>0). M1024 and native M1 do not execute it.
  Native M1 still visits the app method; only its arithmetic is DSP-resident.
  The old six-argument full helper is restored byte for byte. A distinct,
  ARM-only range helper handles global gated rows with chunk-local projection.
  The chunk function has a feature-checked noinline attribute. All new ARM
  functions/calls are excluded on non-ARM. No headers, core/DSP ABI, cache,
  reader count, persistent content buffers, or staging capacities change.

Lifetimes, numerical order, aliases, and errors
  The two pre-existing FC shapes remain 1920+128. Each projection host_view
  is consumed before the next RPC can reuse its staging. Both parallel_for
  operations finish their workers before the next backend operation. Global
  gated rows retain the previous two rows across the boundary; only projection
  indexing subtracts first. The arithmetic sequence remains multiply, FMA,
  FMA, post-multiply under the original precise FP scope.
  Before any RPC, all mutable tensor ranges are checked against input,
  convolution weights, and each other using subtraction-based uintptr_t span
  comparisons. A missing or live-range-overlapping view uses sync_to_host.
  Sampled host bytes are not treated as the full projection. Existing actual
  stageInput/fit/stage/host_view/sync and kept-source machinery is unchanged.
  The output projection starts after both chunks finish. State writes remain
  after both chunks succeed, before output projection as in the old route.
  RPC/sync errors propagate, and a retry passes. There is no new promise that
  partially written output tensors are rolled back on an exception.

Actual unchanged-path codegen and bounded stack
  Own whole-TU before/candidate objects show the original full-row callback
  is exactly the same 59 instructions / 236 bytes. The app's first nine
  instructions, including register saves and SP adjustment, match exactly.
  App frame is 1760 bytes (baseline1760, v1 was1824). The new noinline chunk
  frame is464; the range callback frame is0 and the ranged helper inlines in
  chunk. Known simultaneous app+chunk frames total2224 bytes versus v1's
  known2016, a208-byte increase on the selected2048 route. This is not a bound
  on the whole dynamic backend/thread call stack. The common old full helper
  has no new outlined call. See codegen.json/check_codegen.py and object/.su.
  The entire app method is NOT byte-identical: baseline1965 instructions,
  v2 2053; source guards and code layout are different. Callback restoration
  does not itself prove unchanged timing or explain v1's measured regression.
