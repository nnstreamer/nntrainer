Defect and contract

The fixed-Q8 API enables plain_masters before the first append. Registration
accepts head dimensions that are nonzero multiples of 32, up to 512, and allocates
exactly heads * rounded_max_rows * hd bytes for each master. The public header
permits rewriting rows. Consequently the device fixture's A/B/A appends are legal.

The old xor80_copy loop copies 128 bytes for each i < n. For hd=64 it reads the
unwritten half of worker-local q[512] and writes the next plain row. For 8 heads,
1024 rows and hd=64, the final row starts at 524224, while the allocation ends at
524288; the last 128-byte store ends at 524352, 64 bytes beyond the allocation.
Eight row workers additionally overwrite the first 64 bytes of adjacent worker
ranges at row boundaries 128, 256, 384, 512, 640, 768 and 896. This is a real
ordering race, not a requirement that A/B/A rows must be fresh allocations.
Other legal dimensions with a nonzero remainder modulo 128 have the same defect.

The actual fixed quantizer already writes precisely hd bytes. The bug is in the
following copy. The three helper call sites copy q to kt4 and v4 with n=hd, or
copy 32 contiguous master rows to stage_v with n=32*hd. Sources and destinations
are disjoint. The stage size is divisible by 128 for every legal head dimension.
static-contract.json records the complete dimension and extent proof.

Minimal correction

The patch bounds the original vector loop to n & ~127u, preserving its load,
xor and store body, then copies each remaining byte with src[i] ^ 0x80u. Every
access now falls within [0,n). For existing full-vector dimensions, the byte
operations are unchanged and the tail is empty. No quantizer, FP operation,
scale, state, allocation, row stride, worker partition, wait or cache changes.
No new buffer or persistent metadata is introduced. The affected helper is
inside the Hexagon implementation; the ordinary non-Hex path stays unchanged.

Independent validation

The reviewer copied frozen production and test sources to this directory and
executed the actual-source extraction runner. It uses the production
quant_rows_worker and xor80_copy, actual HVX fixed quantization via SDK libnative,
actual registration/fixed-scale metadata from the baseline host TU, and the
production pthread pool. ASan and UBSan are fatal with no sanitizer suppression.

3,094 copy cases passed: every size 0..512 at offsets 0,1,4,31,63,127, plus the
16 legal complete-stage sizes. Following source/destination tails are poisoned
and surrounding bytes are checked. 384 actual worker A/B/A cases passed across
all 16 legal head dimensions, reverse completion and pthread execution,
1/2/4/8 workers, full 64-row and partial append ranges including the last row.
Complete masters, scales and sums are compared; untouched rows remain intact.
The middle B has independently asserted different quantized bytes. A draft
periodic-seed issue was corrected before these frozen tests; this review uses
fixture b0e57b26 and runner c6ff2123, recorded in checks/strict/results.json.

The unmodified baseline independently fails the dedicated hd64 copy with an
ASan heap-buffer-overflow and fails the actual reverse-order row worker with a
master-byte assertion. The corrected implementation passes both regressions.
Expected baseline failures are separate logs, not suppressed candidate errors.

This fixture validates ownership and actual HVX byte/quantization behavior.
It does not execute HMX, tile baking, FastRPC or device cache behavior. The
original device fixed-Q8 control failure is consistent with the proven defect,
but a successful repaired device A/B/A remains a separate root-run validation.
The raw-plane candidate had not run when that original control failed.
