Capability, ownership and memory

The three real IO producers are direct prefill, direct decode and combined
Q-step in test/htp/nntr_hvx_attn_q.c. Each zero-initializes the whole internal
struct. Only Q-step publishes q_cached=1, after the existing successful scratch
reservation and completed K/V/Q DMA copies. hexkl_moe_dma_copy drains before
return. Allocation failure and direct RPCs leave the capability zero.

At 2048 the existing cached scratch contains K 2 MiB, V 2 MiB, Q 16 MiB and
output 16 MiB. The KV append completes its worker work before attention and
does not reserve or replace this scratch. Q and output are adjacent disjoint
ranges. Q remains immutable for the synchronous RPC. No lifetime is extended
across an RPC, and no DMA drain or worker completion boundary is shortened.

The new private guard requires the completed-cache capability, dynamic Q8,
full 2048-token attention, 32/8 query/KV heads, head dimension 64, G4,
Br128/Bc256/GBr512, row stride 2048, no sinks/window/softcap, bounded head and
chunk indices and the validated layout extent. It rejects overlap of all Q
with VTCM, the actual scale/zp write regions and output. Address-difference
checks avoid integer addition overflow. Real-entry allocation/shape validation
establishes the underlying metadata and VTCM objects before this guard runs.

The selected path uses the old allocations and capacities. It retains the
whole Qx region and the existing metadata arrays; it does not allocate scratch,
cache weights, change readers, or alter C16/PAGE0/preload. q_cached is one new
32-bit field in a DSP-local IO descriptor (24 to 28 bytes on the DSP). The
new synchronous group context contains seven 32-bit fields/pointers, 28 bytes.
Compiled helper frame is 32 bytes and worker frame 640 bytes. Caller frames
remain prefill 1536 bytes and Q-step 336 bytes. No persistent state is added.

Arithmetic, address and concurrent-worker proof

The old flattened row m corresponds to query qb0*128+floor(m/4) and head
n*4+m%4. The new group g starts at Q+qb0*128*2048+n*4*64+g*2048 and uses rows
at offsets 0, 64, 128 and 192. Independent enumeration checks all 65,536
query/head rows in chunks 9+7 across eight KV heads. The final read endpoint
is exactly 16 MiB. It also checks 32,768 distinct aligned AH vector stores
and 144 worker partitions for worker counts 0 through 8.

The direct helper invokes the existing quant_row_params_one and pack_group_rows
bodies. Input bits, per-row operation order, AH layout, scale=1/zp=0 defaults
and final scale fold are preserved. The worker's ranges are disjoint in both
AH vectors and row metadata; its stack context stays alive until the pool's
synchronous acquire barrier completes. The API is deliberately narrow:
k=64, group stride 2048, and 128..2048 groups in multiples of 128. Its exact
packed output extent is groups*4*k bytes, without padded/partial AH rows.

The v81 compilation independently found all 11 existing quantizer function
bodies byte-identical, with only the two new functions added. This comparison
uses relocatable function bytes, not final relocated addresses or performance.
Shared mathematical helper source bodies are also text-identical. The new
worker uses the actual unaligned HVX load contract, not a vector-aligned input
assumption. No arithmetic simplification or quantization policy changes.

Qx and dequant overlap lifetime

The planner is unchanged. The existing nine-block Qx region is 1,179,648 bytes;
the raw deferred QK bank occupies 524,288 bytes. Initial QK always writes L.acc
and converts immediately. Later deferred QK writes every raw tile in Qx before
submitting its dequant worker. That worker uses the other S bank while PV uses
L.acc. Existing success/error joins finish before next reuse or return.

Thus skipping the initial gathered FP32 Qx contents does not leave data that
the overlap pipeline needs uninitialized. Independent source equality covers
dequant_s_at, dequant_s, qx_dequant_available, dequant_worker, phase_qk,
run_q_block and phase_store. The poisoned-Qx host runner also exercises the
existing partial-chunk, worker, QK failure and PV-error drain cases.

Fallback and deployment contract

1024, decode, fixed/Gemma attention, unsupported geometry/stride and unstaged
calls retain the old gather/quantizer path. This is a semantic fallback proof,
not a claim that the extra branch or final linked layout has zero timing cost.
No Gemma device benchmark was run by this reviewer.

The IO field is internal to the DSP, with no IDL/RPC method or ARM ABI change.
The dependency closure is four C translation units: hvx_quant_u8.c,
hexkl_attn_q.c, nntr_hvx_attn_q.c and hvx_attn_decode_q.c. All consumers of
the changed internal IO definition must be rebuilt together; mixing old
descriptor producers with new consumers is outside the deployment contract.
The old hvx_quant_u8.h is unchanged. A new narrow header avoids rebuilding
unrelated FC/MoE users. Repository searches found the three zero-initialized
IO producers above. All four before/candidate TUs compiled and assembled
independently with recorded v81 -O3 -Wall -Werror flags. The decode object and
assembly are byte-identical. Changed-line clang-format 14 checks pass for all
five production files.

Resolved validation finding: initial host alignment model

The earlier tests.patch ffb26aa0 mapped HVX_UVector to the host SDK struct with
8-byte alignment, while the test intentionally supplied Q at q_alloc+1 float.
Author logs reported numerical PASS but contained eight recoverable UBSan
alignment errors. This reviewer reran with halt_on_error=1 and reproduced a
fatal failure at hvx_quant_u8.c:50. Those logs and the initial patch are retained
under rejected-host-shim/; they are not described as a sanitizer pass.

The actual Hexagon SDK declares HEXAGON_UVect1024 with aligned(4). The author
fixed only the host fixture shim to model that type, added size/alignment static
assertions, and enabled -fno-sanitize-recover=all plus explicit fatal runtime
options. Production a07332 remained unchanged. The final frozen f962d48 run
passes all 576+31 cases and five mutants with zero sanitizer runtime errors.
