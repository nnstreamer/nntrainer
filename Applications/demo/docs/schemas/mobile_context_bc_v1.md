# 모바일 최근 앱 예측 입력 계약 v1

적용 데이터는 `data/personalization_bc_observed_v1`이다. 이전 세트는 변경하지 않는다. 예측 시점은 Android 최근 앱 화면을 연 순간이며 이후 5분 이내 처음 사용/재개하는 앱을 감독한다.

`input`에는 아래 다섯 키만 허용한다. 기계 검증 원본은 같은 데이터 폴더의 `input.schema.json`이다. 정의되지 않은 키는 거부하며 임의의 카테고리를 추가하지 않는다.

| 키 | 형식 | 의미 |
|---|---|---|
| time | HH:MM 문자열 | 기기의 현재 현지 시각 |
| moving | boolean | 이동 중인지 여부만 표현 |
| calendar | null 또는 {start, end, title} | 당일 일정 하나의 시작/종료 HH:MM과 사용자가 입력한 제목. 없으면 null |
| notification | null 또는 문자열 | 현재 화면에 표시된 가장 최근 알림 한 건의 짧은 본문 그대로. 없으면 null |
| recent_apps | 앱 ID 네 개 배열 | 과거→최근 순. 마지막 원소가 가장 최근 앱. 향후 사용 앱은 포함 금지 |

예를 들어 일정 제목은 `민수 생일`, `온라인 스터디`다. `사업 송금`, `미처리`, `가족`, `정산`, `다음에 토스를 열기` 같은 모델용 해석 결과를 별도 필드나 문장으로 덧붙이지 않는다. 실제 알림 본문에 `밥값 8천 원 보내줘`가 있는 것은 관측된 내용이다. 알림을 읽었다고 이체 완료로 해석하지 않는다. 본 실험의 화면 관측은 합성이며 실제 Android 수집 파이프라인은 구현하지 않는다.

캘린더는 당일 기준이라 자정 경과 일정은 이번 버전에서 다루지 않는다. 원문은 최대48자, 제목은 최대20자로 제한한다. 앱 기록은 네 번의 최근 실행/재개 기록이며 중복 앱도 허용한다. 후보 앱 설명, 사용자 ID/직업/관계, 시나리오 이름, 정답, 선호와 정답 분포는 `input`과 렌더된 prompt에 들어가지 않는다.

학습 JSONL의 `answer`, `answer_app`, `user_id`, `case`, `variant`, `notification_role`, `reference_probs`, `required_top4_app_ids`는 감독·평가·합성 provenance 메타데이터다. Prompt는 검증된 `input`에서 만든 `context`, 고정 질문 `다음 앱?`, 공통 선택지만 사용한다. 페르소나는 개인별 LoRA 선택으로만 구분한다.

고정 앱 ID/letter는 데이터의 `app_catalog.json`으로 배포한다. J는 `ibk_bank`/기업은행이다. 기존14클래스의 `clock`을 대체했으므로 이전 모델 adapter와 혼용하지 않는다. 순서를 임의로 바꿀 수 없다. 스키마나 후보를 바꾸려면 새 버전을 만들고 데이터·모델·지표를 다시 검증한다.
